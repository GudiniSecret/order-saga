# Decisions

## 001. Монорепозиторий, сервисы — независимые Maven-проекты

**Дата:** 2026-10-25

**Решение:** один git-репозиторий; каждый сервис — самостоятельный Maven-проект
со своим `pom.xml` и Maven Wrapper, без общего parent-pom и shared-модулей.

**Альтернативы:**
1. Multi-module Maven с parent-pom и общим модулем для классов событий.
2. Отдельный репозиторий на каждый сервис.

**Почему:**
- Общий модуль с классами событий создаёт связанность на этапе компиляции:
  изменение события требует пересборки и одновременного деплоя всех сервисов,
  а это противоречит независимому деплою микросервисов.
- Отдельные репозитории для одного разработчика — лишние накладные расходы,
  и всё окружение сложнее поднять одной командой.

**Цена:** классы событий дублируются в каждом сервисе, контракт держим
в синхроне вручную.
